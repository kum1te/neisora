## Что внутри

**neisora.** — независимый desktop-клиент YouTube Music с собственным интерфейсом. Персональная главная, миксы, супермикс и плейлисты приходят из YouTube Music; звук воспроизводит mpv. Во время обычного прослушивания веб-приложение YouTube не загружается.

| | |
| :--- | :--- |
| **Твои рекомендации** | Главная, поиск, альбомы, плейлисты и динамические миксы YouTube Music. |
| **Большой плеер** | Обложка, таймлайн и управление; текст можно скрыть, плеер центрируется. |
| **Текст под музыку** | Синхронизация строк и караоке по словам, когда доступны настоящие таймкоды. |
| **Живой фон** | Лента, кольца и волны реагируют на реальный уровень звука. Вид, интенсивность и скорость настраиваются. |
| **Твоё оформление** | Шесть палитр, свои цвета и синхронизация с обоями в поддерживаемом окружении. |
| **Твоя коллекция** | Лайки аккаунта, медиатека по разделам, сохранение альбомов и плейлистов. |
| **На устройстве** | Папки с локальной музыкой, поиск по тегам и встроенные обложки; воспроизведение без интернета. |
| **Твоя очередь** | Ручные вставки, поиск, удаление и перестановка; локальные и YouTube-треки вместе. |
| **История** | Последние 500 прослушиваний на устройстве, даты и поиск. |
| **Медиаклавиши** | Linux MPRIS: управление музыкой без фокуса окна и системная панель плеера. |
| **Нативное аудио** | mpv, предварительная загрузка адреса следующего трека и восстановление оборвавшегося потока. |

Ручной пропуск в миксе передаёт YouTube сигнал skip и сохраняет контекст очереди. Обычный конец трека продолжает текущую очередь. Никаких заранее заготовленных рекомендаций.

Версия **1.0.0** объединяет Linux и Windows, добавляет ручной выбор текста и аудиовыхода. Подробности и ограничения — в [заметках к релизу](docs/RELEASE-1.0.0.md).

## Установка

Windows 10/11 x64: скачай `neisora_1.0.0_x64-setup.exe` на странице релизов. Установщику нужен интернет для WebView2 (если отсутствует) и mpv; загрузки проверяются по SHA-256. Подписи издателя пока нет. [Подробности Windows](docs/WINDOWS.md).

Linux x86_64: **`.deb`, `.rpm`, пакет Arch, AppImage и переносимый архив**. Сборка использует Ubuntu 22.04 / glibc 2.35 как минимальную базу. Проверки установки на нескольких дистрибутивах входят в [Linux CI](https://github.com/kum1te/neisora/actions/workflows/linux.yml).

### Готовые пакеты

Скачай пакет своей системы на [странице релизов](https://github.com/kum1te/neisora/releases). Проверь его по опубликованному `SHA256SUMS`, затем установи:

```sh
# Ubuntu / Debian
sudo apt install ./neisora_1.0.0_amd64.deb

# Fedora
sudo dnf install ./neisora-1.0.0-1.x86_64.rpm

# Arch / EndeavourOS
sudo pacman -U ./neisora-1.0.0-1-x86_64.pkg.tar.zst
```

Для запуска без установки — [AppImage](docs/LINUX.md#appimage): скачай файл, разреши выполнение (`chmod +x`) и открой. Внутри уже есть mpv, Python и библиотеки интерфейса.

Node.js и yt-dlp включены в пакеты с зафиксированными версиями. mpv, Python 3, GTK и WebKitGTK устанавливаются пакетным менеджером. ImageMagick нужен только для цветов обоев. Переносимый архив тоже использует системные библиотеки; подробности, требования и диагностика — в [инструкции для Linux](docs/LINUX.md).

### Из исходников

Нужны Node.js 22.12+, pnpm 10, Rust 1.96, GTK 3 / WebKitGTK 4.1 development packages, libdbus-1 development package, OpenSSL, mpv и Python 3. Для полного комплекта пакетов также нужны `zstd`, `patchelf` и инструменты сборки своей системы.

```sh
git clone https://github.com/kum1te/neisora.git
cd neisora
pnpm install --frozen-lockfile
pnpm release
sh tools/install.sh
~/.local/bin/neisora
```

Локальный установщик копирует готовый бинарник и компоненты в отдельный каталог версии, обновляет меню и иконки. Вход сохраняется при обновлении. Для распространяемых пакетов используй `sh tools/linux-release.sh` на Ubuntu 22.04; сборка на новом Arch требует новых системных библиотек.

### 3. Подключение аккаунта

Открой **Настройки → Аккаунт → Войти через Google**. Можно использовать отдельное окно входа либо явно импортировать сессию из поддерживаемого браузера. Пароль вводится на странице Google; приложение его не принимает.

Без входа доступны гостевые рекомендации. Персональные миксы, медиатека и отметки «Нравится» требуют аккаунта. Используемое воспроизведение проверено без Premium.

## Сделай своей

В **Настройки → Оформление** доступны готовые палитры, редактор цветов и параметры визуализатора. Поиск обоев поддерживает GNOME, Cinnamon, MATE, KDE Plasma, XFCE и QuickShell / Illogical Impulse. Фактическая доступность зависит от настроек рабочего стола; динамические и удалённые обои могут не определяться.

В **Настройки → Локальная музыка** подключи папки с файлами; коллекция появится в **«На устройстве»**. Исходные файлы остаются на месте. У треков есть действия «следующим» и «в очередь», в очереди — поиск, удаление и перестановка. [Подробности локальной музыки и смешанной очереди](docs/LOCAL-MUSIC.md).

Медиатека разделена на плейлисты, альбомы и треки. Лайки и сохранение коллекций связаны с аккаунтом YouTube Music; удаление из медиатеки не удаляет сам плейлист. История neisora хранит до 500 прослушиваний локально и записывает трек после пяти секунд звучания. Её можно искать и очистить; она не синхронизируется с историей Google.

Медиаклавиши на Linux работают через MPRIS. Доступны воспроизведение, пауза, стоп, следующий/предыдущий трек, перемотка и громкость; подробности для окружений с ручными привязками — в [инструкции Linux](docs/LINUX.md#медиаклавиши).

В **Настройки → Аудиовыход** можно выбрать устройство. При отключении временно используется системный выход; сохранённое устройство восстанавливается после подключения.

Большой плеер открывается из нижней панели. Кнопка выбора версии текста позволяет посмотреть запись LRCLIB, сохранить её для трека или вернуть автоматический подбор. Поделиться текущим треком можно рядом с лайком в нижнем плеере. Текст приходит из YouTube Music, LRCLIB и KuGou; если текста там нет, используется обычный текст Genius. Если у записи есть таймкоды слов, включается караоке; если есть только строки — подсвечиваются строки. Обычный текст остаётся обычным текстом. Смещение можно поправить отдельно для каждой песни. Для музыкальных клипов подбирается соответствующая аудиозапись; у клипа с вступлением может потребоваться поправка смещения. [Подробнее о поиске текстов и обложек](docs/LYRICS.md). Превью видео и аватары заменяются подходящей квадратной обложкой из каталога YouTube Music или Deezer, если совпали название, исполнитель и версия записи; при ошибке загрузки остаётся оригинал.

## Приватность и безопасность

У neisora нет своего облачного бэкенда и аналитики. Сессия хранится локально; музыкальные запросы уходят в YouTube, а названия, исполнители и длительность — также источникам текстов. Google cookies им не передаются.

Перед первой публикацией выполнены проверка зависимостей, обзор границ IPC и регрессионные тесты безопасности. Область проверки, результаты и известные ограничения описаны в [отчёте](docs/SECURITY.md). Для `glib` включён документированный backport исправления; остаётся предупреждение о неподдерживаемом build-time `proc-macro-error`. Это не независимый аудит и не гарантия отсутствия уязвимостей.


Интерфейс тестируется в настоящем WebKit-окне с фикстурами; инструкция — в [tools/README.md](tools/README.md).

<details>
<summary>Архитектура и ограничения</summary>

- **Svelte 5 + TypeScript** — собственный интерфейс.
- **Tauri 2 + Rust** — локальный бэкенд, запросы, очередь и настройки.
- **yt-dlp + mpv** — извлечение медиапотока и воспроизведение.
- **YouTube Music / LRCLIB / KuGou** — тексты и доступные таймкоды.

YouTube Music используется через неофициальный API: изменения сервиса могут влиять на работу клиента. Версии включённых компонентов указаны в `tools/runtime-manifest.json`; они обновляются вместе с приложением. Автозагрузка исполняемых обновлений отключена.

Исторический идентификатор `local.kumite.vesper` сохранён, чтобы обновление названия не сбрасывало существующий вход и настройки. Локальные профили, cookies, логи и сборки не входят в репозиторий.

</details>
