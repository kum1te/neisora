# neisora 0.7.0 — подготовка beta

Ветка `main`; публикация Linux-пакетов 0.7.0 ещё не выполнена. Последний опубликованный Linux-релиз: 0.6.3.

## Управление музыкой

- Повтор: выключен → вся очередь → один трек. Кнопки в обычном и большом плеере; режим сохраняется.
- Повтор одного трека срабатывает при естественном окончании. Ручной Next по-прежнему пропускает трек.
- Повтор очереди возвращает к началу конечного плейлиста, после загрузки всех продолжений. Супермикс остаётся живым радио и не закольцовывает обрезанную историю.
- Linux MPRIS: LoopStatus читается, меняется и отправляет PropertiesChanged.
- M: mute с возвратом прежней громкости; R: повтор; ←/→: seek на 5 секунд; Ctrl/Cmd+K: поиск. Справка в настройках.
- Таймлайн остаётся тонким, но область захвата увеличена до 22 px.

## Плейлисты YouTube Music

- Создание в медиатеке, с приватностью PRIVATE по умолчанию; название, описание, личный / по ссылке / открытый доступ.
- В меню трека: добавить в существующий или новый плейлист. Длинная медиатека загружается страницами.
- В своём плейлисте: изменить название/описание/доступ, удалить с подтверждением, убрать трек, переместить выше/ниже.
- Удаление и перемещение адресуют конкретный setVideoId: повторяющийся videoId не приводит к удалению другого дубля.
- Перед записью backend заново проверяет серверный editable header и соответствие playlistId. Флаг из интерфейса не даёт права редактирования.
- Изменения сериализуются; смена аккаунта блокирует устаревший запрос. Сервер должен подтвердить успех. Ошибка не закрывает форму и не маскируется успешным уведомлением.
- Локальные файлы не отправляются в YouTube Music.

Форматы сверены с протоколом открытого клиента [ytmusicapi](https://github.com/sigma67/ytmusicapi/blob/main/ytmusicapi/mixins/playlists.py). UI-тесты используют изолированные ответы; создание и появление плейлиста в обычном YouTube Music подтверждено пользователем; **остальные операции на настоящем аккаунте остаются ручной проверкой**. Тесты не изменяют существующие пользовательские плейлисты.

## Узкие окна

- Минимальный размер 420×440 логических px вместо 900×600.
- Компактная боковая навигация, двухрядный нижний плеер, перенос элементов настроек и локальной коллекции.
- Лайк больше не скрывается при ширине меньше 1150 px. Обязательные действия остаются доступными.
- Большой плеер перестраивается для узких и невысоких окон; очередь накладывается поверх контента, не сжимая его до нечитаемого состояния.

## Проверки

Набор `tools/gui-checks.sh` дополнен реальными проверками WebKit: EOF/Next/repeat, MPRIS LoopStatus, формы playlist CRUD и ошибки, дубли треков, геометрия и попадание указателя в основные действия на 1360/1024/800/640/480/420 px. Rust проверяет команды, идентификаторы, права из ответа сервера и подтверждение результата; IPC security tests проверяют отклонение неизвестных/некорректных действий.

Локально прошли 58 Rust-тестов (2 внешних теста пропущены), 11 тестов очереди/повтора, Clippy и проверка Svelte. Полный WebKit-набор, 100 циклов открытия/закрытия плеера и проверки границы IPC/CSP прошли. Production-сборка на Ubuntu 22.04 и установленная 0.7.0 в Hyprland проверены на синтетических локальных WAV: настоящий mpv EOF повторяет один трек и возвращает конечный плейлист к началу; проверены seek, громкость, LRC, история и MPRIS. Профили изолированы; пользовательская Google-сессия не используется.
